# `adapter-psm-test/src/test/java/hu/blackbelt/judo/meta/expression` — shared northwind-style PSM fixture that every PSM adapter test inherits

| File | Purpose |
|---|---|
| `ExecutionContextOnPsmTest.java` | Builds the demo PSM model every PSM adapter test runs against. Exposes public fields `psmModel`, `expressionModel`, `psmUtils` and `setUp()`, which populates the model, asserts `psmModel.isValid()`, then runs `PsmEpsilonValidator.validatePsm` expecting zero errors and zero warnings — a fixture edit that breaks a PSM EVL constraint fails every subclass at setup, before any assertion. Model `demo` carries packages `measures`, `entities`, `types`. Measures: `Time` (nanosecond…week plus `halfDay` and `minute`, both intentionally left WITHOUT `unitType` so unit-type-less duration paths are covered), `MonthBasedTime` (`month`, `year` — the pair `getBaseDurationRatio` must reject), `Mass`, `Length`, and derived `Velocity` (metre¹, minute⁻¹), `Area` (nanometre²), `Force` (nanosecond⁻², milligram¹, nanometre¹). Terms index units positionally (`length.getUnits().get(6)`, `time.getUnits().get(5)`), so reordering a unit list silently redefines the derived measure. Types include measured primitives `kg`/`cm` whose `storeUnit` is resolved by SYMBOL lookup over the whole resource set — renaming a symbol breaks fixture construction. Entities model northwind (`Product`, `Customer`, `Company` extends `Customer`, `Order`, `InternationalOrder`, `OrderDetail`, `Shipper`, `Category`, `Address`, `InternationalAddress`, `Employee`) with partnered association ends `products`↔`category` and `orders`↔`employee` and containments `orderDetails`, `addresses`. Package-private `getMeasureElement(Class)` streams `psmModel.getResourceSet().getAllContents()` in parallel. `setUp()` is NOT annotated `@BeforeEach` — subclasses must call it explicitly. |
